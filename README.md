# AiDe Bot

MAX-бот на Go.

## Запуск

```bash
cp .env.example .env
go mod tidy
make run
```

Docker:

```bash
docker compose up --build
```

## Проверки

```bash
make check
```

## Фотографии

Бот принимает одну фотографию JPEG/PNG до 10 МиБ на сообщение, с подписью или без.
Файл скачивается по HTTPS-ссылке вложения MAX без передачи токена бота файловому
серверу. Тип проверяется по содержимому, размер ограничен при чтении.
PDF, другие вложения и несколько фото отклоняются с пояснением пользователю.

Фотография отправляется в `POST /api/v1/process` как multipart с полями `message_id`,
`chat_id`, `user_id`, `text`, `file`; текстовые сообщения сохраняют JSON-контракт.
Распознавание и работа LLM выполняются бэком. При ошибке OCR бот показывает сообщение
пользователю; при других ошибках бэка сообщает о недоступности сервиса.

`BACKEND_REQUEST_TIMEOUT=10m` задаёт общий предел ожидания ответа бэка с OCR и LLM.
В Kubernetes бот обращается напрямую к `http://aide-backend.apps.svc.cluster.local`
по пути `/api/v1/process`, обходя таймауты публичного ingress. При использовании
внешнего URL согласуйте таймауты и лимит загрузки прокси с этими настройками.
Обработка событий остаётся последовательной: долгий запрос задерживает следующие
события. Повторная отправка фото запускает новое распознавание.

Перед выкладкой бота обновите бэк до версии с поддержкой multipart. Если конфигурация
управляется через Headlamp, обновите `BACKEND_API_BASE_URL`, `BACKEND_MESSAGES_PATH`
и `BACKEND_REQUEST_TIMEOUT` в существующем `aide-bot-config` и перезапустите Deployment.
